# B05 — Integración continua

- Fase: F1 Cimientos
- Módulo: Plataforma
- Depende de: B02 · B03 · B04
- Bloque crítico (requiere revisión externa): No

## Lectura obligatoria del manual (docs/manual)
- capítulos 8, 11, 13
- Capítulos 12 (base de datos), 13 (backend), 14 (API), 15 (seguridad) y 16 (interfaz) en lo que aplique
- Capítulo 21: definición de terminado

## Entregables
- Flujos de GitHub Actions con las diez verificaciones del numeral 11.4
- Protección de la rama principal; Renovate configurado
- Construcción de imágenes Docker y análisis con Trivy

## Criterios de aceptación
- [ ] Un pull request con una prueba rota no puede integrarse
- [ ] El tiempo total de las verificaciones es inferior a 15 minutos
- [ ] `pnpm check` en verde
- [ ] Pruebas de permiso denegado, aislamiento entre empresas y auditoría
- [ ] Documentación y cierre del bloque escritos

## Encargo para Claude Code
```text
Vamos a construir el bloque B05 — Integración continua.

1. Lee docs/bloques/B05.md, los capítulos del manual que cita y el código
   relacionado que ya existe.
2. Antes de escribir código, preséntame un plan: qué archivos vas a crear o cambiar,
   qué tablas y puntos de la API, qué pruebas, y cualquier duda o decisión que
   necesite mi aprobación. No avances hasta que yo apruebe el plan.
3. Implementa el bloque en la rama feat/b05-integracion-continua, con commits pequeños.
4. Escribe las pruebas junto con el código, incluidas las de permiso denegado,
   aislamiento entre empresas y auditoría.
5. Ejecuta pnpm check y corrige hasta que todo pase. No debilites ninguna prueba
   ni control para lograrlo.
6. Actualiza la documentación del módulo y escribe docs/bloques/B05-cierre.md con:
   qué se construyó, cómo lo pruebo yo paso a paso en mi navegador, qué quedó
   pendiente y qué decisiones tomaste.
7. Abre el pull request y dime exactamente qué debo revisar.

Recuerda: no soy desarrollador. Explícame en español claro y sin jerga.
```
